System guide

How TrustedCert turns a certificate into a verifiable record.

TrustedCert combines institution wallet roles, Ethereum smart-contract records, and IPFS file storage so a certificate can be checked without relying on a private email thread or manual registrar lookup.

For verifiers

Paste a certificate ID and compare the returned recipient, title, issuer, and status.

For institutions

Upload a certificate, pin the file, and write its metadata to the certificate registry.

For admins

Approve trusted issuer wallets, revoke access, and pause the registry if needed.

01

Approve an issuer

A platform admin registers an institution name, description, and wallet address. The smart contract grants that wallet the institution role.

02

Upload the certificate

The institution uploads the certificate file through the backend. The backend pins it to IPFS and returns the content identifier, keeping storage credentials private.

03

Register metadata

The registrar submits the recipient name, certificate title, IPFS CID, and optional external ID to the smart contract. The contract emits a certificate ID.

04

Verify publicly

Anyone can enter the certificate ID to retrieve the on-chain record and open the attached certificate preview from IPFS.

What lives where

Each layer has a narrow job, which keeps verification fast and tamper-resistant.

Frontend Verifier, institution dashboard, admin dashboard, wallet connection
Backend Public contract config and private IPFS upload proxy
Ethereum Issuer roles, certificate metadata, revocation status, platform pause control

Verification notes

Details that help users interpret a certificate result correctly.

What proves the certificate is authentic?

The certificate ID resolves to a smart-contract record created by an approved institution wallet.

What does revocation mean?

The issuing institution marked the certificate as no longer active. The record remains visible, but the status changes.

Why is the file stored separately?

The file is stored on IPFS so the blockchain only needs to keep compact metadata and the content identifier.
